# Muse v1 specification, part 2: the experience on desktop and phone

Written 2026-11-13. Part 1 is the modules (`01-architecture.md`); part 3 is the build plan (`03-plan.md`). This replaces `docs/muse-plan.md` §6.4 and extends the mock-up in `docs/mockups/`. First language is Traditional Chinese; English ships with it; Japanese and Korean follow the first Taiwan users.

The person this is for does not know what an API key, a token or a model is, and should not need to learn.

---

## 1. Rules for every screen

1. **One question per screen.** Each screen answers one thing the person would ask out loud.
2. **Plain words.** The words below are the only ones used in the main screens. Model names, tokens and addresses sit behind a "Details" control.

   | We say | Not |
   |---|---|
   | Helper (小幫手) | Agent, bot |
   | Service (服務) | Provider, API |
   | Allowance (額度) | Quota, rate limit |
   | Refills at 16:00 (16:00 補滿) | Resets |
   | Permission (授權) | Mandate, scope |
   | Record of what was done (紀錄) | Receipt, log |
   | Always-on helper (常駐小幫手) | VM, server |
   | Kept on your devices (留在你的裝置) | End-to-end encrypted |
   | AI on this computer (這台電腦上的 AI) | Local model |
   | Key (金鑰), only inside the connect-a-service flow and For apps | API key, token |

3. **Three choices, never a dead end.** When something cannot happen now, the person sees up to three buttons, in this order and only the ones that are real: **Wait until 16:00**, **Open in my ChatGPT**, **Spend about NT$1.3**. The router supplies exactly these (the `options=` trailer).
4. **Every change is a card.** Anything that writes, sends or spends shows a card with what, where, under which permission, and what it costs. Approve or decline. Nothing else is modal.
5. **One switch stops everything.** Pause is reachable in one tap from every screen and takes effect on every device.
6. **Say what was not done.** A partial result with a clear note, never a confident guess.
7. **Money is shown as money.** Amounts in the person's currency with the US dollar figure in details. "Nothing spent" is said explicitly.
8. **Nothing to memorise.** No passwords made by the person except the optional vault PIN. The recovery key is printed or saved once, with a check that it was.
9. **Accessible by default.** Text scales with the system setting; contrast meets WCAG AA; every control has a label; no information by colour alone; all flows work with a screen reader and with one hand on a phone.
10. **Same words and order on phone and desktop.** The desktop shows more at once; it never shows something different.

Refill times are shown in the person's own time zone everywhere. (The current mock-up shows 15:00 in one place and 16:00 in another; that is a mock-up error to fix.)

Privacy is shown with three badges, the same everywhere:

| Badge | Meaning | Router class |
|---|---|---|
| **On this device** | Never leaves | `local` |
| **Private** | Goes only to services that do not train on it or let people read it | `private` |
| **Standard** | May go to any connected service; free ones may train on it | `standard` |

`public` exists in the router for content the person marks as already public; it has no badge of its own and appears only in details.

## 2. Layout

### 2.1 Phone

Five tabs at the bottom, thumb-reachable. The pause switch is in the top bar on every tab.

```
┌──────────────────────────────┐
│ Muse                 ⏸ Pause │
├──────────────────────────────┤
│                              │
│        (current tab)         │
│                              │
├──────────────────────────────┤
│ Today  Ask  Chores  Records  More │
└──────────────────────────────┘
```

"More" holds Services, Permissions, Devices, Wallet (once it exists, section 4.8), Settings. A red dot on Today means something is waiting for a decision.

### 2.2 Desktop

A sidebar with the same items in the same order, all visible, except Wallet, which appears once the person has a spending permission or a payment (section 4.8). A menu-bar (tray) icon shows the gauge and opens a small panel.

```
┌────────────┬───────────────────────────────────────────────┐
│ Muse       │                                      ⏸ Pause  │
│            │                                               │
│ Today      │              (current screen)                 │
│ Ask        │                                               │
│ Chores     │                                               │
│ Records    │                                               │
│ ────────   │                                               │
│ Services   │                                               │
│ Permissions│                                               │
│ Devices    │                                               │
│ Wallet     │                                               │
│ For apps   │                                               │
│ Settings   │                                               │
└────────────┴───────────────────────────────────────────────┘
```

"For apps" exists only on desktop: it gives other programs Muse's endpoint with a key each.

### 2.3 What each device can do **(assumes the phone is viewer and approver first)**

| | Desktop | Phone | Always-on helper |
|---|---|---|---|
| Ask the helper | Yes | Yes (answered by the home) | — |
| Run chores | Yes, while on | No | Yes, always |
| Approve cards | Yes | Yes | — |
| Connect a service | Yes | Yes | — |
| Give other apps the endpoint | Yes | No | Yes, for apps on it |
| Read private records | Yes | Yes | Only with a permission for that job |
| Pair a device | Yes | Yes | By QR from another device |

If the phone is the person's only device and there is no always-on helper, Ask works while the app is open and chores are offered with a note: "Chores need a computer or an always-on helper. Add one?".

## 3. First run

Target: a first answer in under a minute with four taps and no key. The same on phone and desktop.

| Step | Screen | What the person does |
|---|---|---|
| 1 | **Welcome.** Language. Two sentences: "Muse is a helper that does small jobs using the free allowances of services you sign up for. It spends nothing unless you say so." | Tap Continue |
| 2 | **First service.** One button: "Connect OpenRouter (about 30 seconds)". Under it, two plain facts: "50 requests a day for free. Some of its free models may learn from what you send." A text link: "Use the AI on this computer instead" (desktop, if one is found). | Tap; approve on OpenRouter's own page; return automatically |
| 3 | **Try it.** A text box and three suggestions ("Summarise a file", "Plan my week", "What can you do?"). | Ask or pick |
| 4 | **Answer**, with one line beneath: "Answered by OpenRouter. Nothing spent." Then a card: "Keep your things safe: save your recovery key." | Read; open the card |
| 5 | **Recovery key.** 24 words from the standard word list in the app's language (lists exist for Traditional Chinese, English, Japanese and Korean), with Print, Save as file, and "I'll do it later" (which leaves a reminder on Today until done). One sentence: "If you lose all your devices and this key, nobody can open your records, including us." | Save, then re-enter three of the words to confirm |

Device lock: the app asks for biometrics or a PIN the first time something private is stored, not before.

After the first answer the helper proposes the next service once, when it would have helped: "That would have been faster with one more service connected. About 2 minutes, 3 steps."

## 4. Screens

Each screen lists what is on it, the states it must handle, and what differs between phone and desktop.

### 4.1 Today

**Answers:** can my helper work right now, and will it cost me anything?

```
┌──────────────────────────────┐
│  Free allowance today        │
│  ████████████░░░░  72% left  │
│  Next refill 16:00 (Gemini)  │
│                              │
│  Spent today   NT$0 of NT$30 │
├──────────────────────────────┤
│ ● Needs you (1)              │
│  Save "Weekly digest" to     │
│  Documents?   [Approve] [No] │
├──────────────────────────────┤
│ Running                      │
│  Indexing your files  41%    │
│ Done today                   │
│  Morning digest      08:02   │
│  Contract question   10:15   │
├──────────────────────────────┤
│ Tip: connect Cerebras (+1min)│
└──────────────────────────────┘
```

- **Gauge.** One bar for today's free allowance across services, weighted by what each can do, with the soonest refill. Tapping it opens Services. An estimate is marked "about".
- **Needs you.** Cards waiting for a decision, newest first. This is the only place a red dot comes from.
- **Running / Done today.** One line each; tapping opens the record.
- **Tip.** At most one suggestion, dismissible, never more than one a day.
- **States.**
  - Nothing connected: the gauge is replaced by "Connect your first service".
  - All allowances used: gauge at zero with "Refills at 16:00" and the three choices.
  - Paused: a full-width bar "Everything is paused" with Resume.
  - Home unreachable (phone, VM down): "Can't reach your always-on helper. Last seen 14:02." with Retry and "Use this device for now".
- **Desktop.** Three columns: gauge and spending; Needs you; Running and Done. The tray panel shows the gauge, spending, and the first waiting card.

### 4.2 Ask

**Answers:** what do I want done now?

- A conversation. The input has a privacy badge the person can change before sending (default from Settings) and an attach button.
- Under each answer, one grey line: which service answered and what it cost, for example "Used your Groq allowance (refills in 3 h). Nothing spent." Tapping it shows details: model, tokens, whether the cache answered.
- A button under each answer: "Open in my ChatGPT / Claude / Gemini". It opens the person's own app with the question. Nothing is routed through the subscription.
- When the helper wants to change something, the card appears in the conversation and on Today.
- When the router cannot answer now, the three choices appear in place of the answer.
- "Make this a chore" under any answer turns the request into a scheduled chore with one confirmation.
- The Private badge needs a service whose terms qualify, or the AI on this computer. The demo data should include one such service so the badge can be shown working.
- **States.** Offline: the question is queued with "Will be asked when you're back online". Private question with no private service: "No connected service keeps this private. Use the AI on this computer, or change the badge."
- **Desktop.** Conversation list on the left, conversation in the middle, a details panel on the right that can be closed.

### 4.3 Chores

**Answers:** what does my helper do for me without being asked?

- A list in plain sentences: "Every Monday 08:00, summarise these 5 feeds into Documents/Muse." Each shows its last result, next run, and budget ("up to 40 requests, nothing paid").
- Add: type a sentence. The helper shows what it understood (what, when, where the result goes, the budget, which permission it needs) for one confirmation. If a permission is missing, the card to grant it comes first.
- Each chore: Run now, Pause, Edit (as a sentence), Delete, and its history.
- Spare-allowance chores are labelled "Runs when there is allowance to spare" with the typical time.
- **States.** No home that can run chores: the note from section 2.3. A chore that failed its own check twice: "Couldn't finish: the summary missed two sources. [See what it got] [Try with a stronger service]".
- **Desktop.** List with a detail pane.

### 4.4 Records

**Answers:** what did my helper do, and can I prove it?

- Every action as a readable line, newest first, grouped by day: time, what, under which permission, cost.
- Filters as chips: "Left my devices", "Cost money", "Changed something", "By chore", by device.
- Tapping a line shows the full record: the permission it used, the device, a link to the result, and "Undo" where the action can be undone (a file written, a draft created).
- A small mark at the top: "All records check out" or "Record 1,204 does not match" with what to do. A second line: "Last sealed today 03:00" (the anchoring), with details behind it.
- Export: a file the person can give to someone else, with a way to check it.
- **Desktop.** A table with the same columns and filters; export in the toolbar.

### 4.5 Services

**Answers:** what is connected, how much is left, and what should I add?

```
┌──────────────────────────────┐
│ Gemini            Standard   │
│ ██████████░░░  about 160 left│
│ Refills 16:00 · good for     │
│ everyday questions           │
├──────────────────────────────┤
│ Groq              Standard   │
│ ████████████░  1,820 left    │
│ Refills 08:00 · fast answers │
├──────────────────────────────┤
│ On this computer  On device  │
│ No limit · private · slower  │
├──────────────────────────────┤
│ + Add a service              │
│   Cerebras · 1 min · no card │
│   Cohere   · 2 min           │
├──────────────────────────────┤
│ Other allowances ▸           │
│ Your subscriptions ▸         │
└──────────────────────────────┘
```

- One card per connected service: what is left (marked "about" when estimated), when it refills, what it is good for, its privacy badge, "Checked 12 Nov" from the catalogue.
- Tapping a card: details, "Test it" (one small request), "Disconnect" (removes the key from this home).
- **Add a service.** Ranked by allowance gained per minute. Each row says how long it takes and whether it needs a card or phone number, or "not confirmed".
  - One-tap services (OpenRouter, Hugging Face once verified): approve on their page, return.
  - Guided services: Muse opens the service's own key page and shows one step at a time beside it. When the person copies the key, Muse offers "Use the key you just copied?". Muse never types into or clicks on the service's site.
  - On a phone the steps appear as a sheet over the browser view.
- **Other allowances.** Storage, computing and chain allowances the person has: shown, not managed yet.
- **Your subscriptions.** ChatGPT, Claude, Gemini apps: "Muse never signs in to these. It only opens them with your question."
- **States.** A service that turned requests away: "Busy right now. Trying again at 14:10." A key that stopped working: "This key was refused. [Reconnect]".
- **Desktop.** A grid of cards; the add flow opens the service page in the system browser with the steps in a side window.

### 4.6 Permissions

**Answers:** what is my helper allowed to do, and how do I stop it?

- One card per permission, written as a sentence: "Your helper may read the folder Documents/Work." "Your helper may spend up to NT$20 a day on 3 services, until 30 Nov." A spending permission can never exceed the daily limit in Settings; if the limit is lowered below it, the lower figure applies and the card says so.
- Each card shows where it is in force, as plain marks: Helper ✓, Spending limit ✓, Records ✓. A mark that is not green says why ("Waiting for your always-on helper to come online").
- **Stop** on every card. One tap, one confirmation, and the marks turn off one by one. The record of stopping appears in Records.
- **Add.** Type what to allow, or pick from common ones. The helper shows the draft as a sentence with its limits and end date; the person approves with biometrics or passkey.
- Permissions the helper asked for and the person declined are listed under "Declined", so the helper does not ask again within a week.
- **Desktop.** Cards on the left; on the right, the selected permission with its history from Records.

### 4.7 Devices

**Answers:** where does Muse run, and is everything in step?

- A list: this device, other devices, the always-on helper. Each shows its role, when it was last seen, and "In step" or "Catching up".
- **Add a device.** Shows a QR code. The other device scans it; both show the same four words; the person confirms on both.
- **Add an always-on helper.** Three steps on one screen:
  1. "Create it" opens Oracle's page with everything filled in (free allowance: 2 processors, 12 GB). A note: "You need an Oracle account. Oracle may ask for a card to check who you are."
  2. "Approve it there."
  3. "Pair it": the app shows a code; pairing completes over the private link.
  Then: "Your always-on helper is ready. Chores now run even when this computer is off."
- The always-on helper's card shows: running since, allowance use of the VM itself against Oracle's free limits, last backup, updates ("Up to date" or "Updates tonight at 03:00"), and "Rebuild from backup".
- **Remove a device / "I lost this device".** Stops its permissions, changes the vault's key for the remaining devices, and says what the lost device could still read until then.
- **Desktop and phone.** Same content.

### 4.8 Wallet (test network; hidden until a paid feature is first used)

**Answers:** what can my helper pay for, and what has it paid?

- A header that never goes away in v1: "Practice money on a test network. Nothing here is real money."
- Balance of practice USDC; today's spending against the limit; the services the helper may pay.
- "Change the limit" opens the related permission.
- A list of payments, each linking to its record.
- Creating the wallet is one passkey prompt. No seed phrase is shown; recovery follows the wallet provider's passkey sync, and the screen says who that provider is.
- Credits (later in v1): a second tab with the person's balance, a note that "credits fade by half every 30 days", and the exchanges that created them.

### 4.9 For apps (desktop only)

**Answers:** how do I let another program use my allowances?

- The address to paste (`http://127.0.0.1:4000/v1`) with a Copy button.
- A list of programs, each with its own key, priority ("While I'm using it" / "Normal" / "When there's allowance to spare"), daily limit, and whether it may use paid services.
- "Add a program" offers presets (a chat window, a coding tool, a script) with the exact fields to paste where.
- Each program is a permission; it also appears on the Permissions screen.

### 4.10 Settings

- Daily spending limit (default NT$30, shown also in US dollars).
- Default privacy badge.
- Language.
- What the helper remembers about you: a readable, editable list. "Forget everything" with a confirmation.
- Recovery key: show again (after biometrics), print, or make a new one.
- Export everything; delete everything.
- About: versions, the catalogue's date, "Check that this installation is genuine" (runs the supply-chain check).

## 5. Cards

All cards share one shape so they can be read at a glance.

```
┌──────────────────────────────┐
│ Save a file                  │  ← what, as a verb
│ "Weekly digest 13 Nov.md"    │  ← the thing
│ to Documents/Muse            │  ← where
│ Under: Weekly digest chore   │  ← which permission
│ Cost: nothing                │  ← always present
│ [Approve]   [Not this time]  │
│ Always allow this ▸          │  ← turns it into a standing permission
└──────────────────────────────┘
```

| Card | Extra line |
|---|---|
| Send or draft a message | The first lines of the text, with "See all" |
| Spend | Amount in local currency, to whom, and what is left of today's limit |
| Grant a permission | The sentence, the limits, the end date |
| Use a one-off trial credit | "This credit does not refill" |
| Send something private to a service | The badge it needs and the services that qualify |
| Install a skill | What it asks for, line by line, and who wrote it |

A card expires if not answered (default 24 hours; 5 minutes for payments). Expired cards go to Records as "Not approved".

## 6. Notifications

| Event | Phone | Desktop | LINE (if connected) |
|---|---|---|---|
| A card needs you | Push with the action; approve from the notification with biometrics | System notification | A reply in the person's own chat, only if they wrote to the helper there in the last day; otherwise one pushed message, budgeted |
| A chore finished | Silent, badge on Today | Tray dot | No |
| A chore failed twice | Push | Notification | No |
| Something was spent | Push, always | Notification | No |
| Daily summary | One push at a chosen time | — | Optional |
| Always-on helper unreachable for an hour | Push | Notification | No |

LINE's free plan allows 200 pushed messages a month and replies are free, so the helper prefers replies and counts pushes as an allowance on the Services screen.

## 7. Key flows, step by step

### 7.1 Add a service by guided key (target: under 3 minutes)

1. Services → Add → Gemini. Screen: "3 steps, about 2 minutes. You'll need a Google account."
2. Muse opens Google's key page. Step 1 of 3 shows beside it: "Tap 'Create API key'."
3. Step 2: "Choose 'Create in new project'."
4. Step 3: "Tap Copy." Muse notices a key-shaped text on the clipboard (only while this flow is open) and asks "Use the key you just copied?".
5. Muse tests it with one small request and shows the new card: "Gemini connected. About 200 more requests a day."

If a step no longer matches the page, "This doesn't look right" reports the guide as outdated and falls back to "Paste your key here".

### 7.2 The three choices (target: one tap)

The strong free service is used up during a report.

```
┌──────────────────────────────┐
│ The best free service for    │
│ this is used up until 16:00. │
│                              │
│ [Wait until 16:00]           │
│ [Open in my ChatGPT]         │
│ [Spend about NT$1.3]         │
└──────────────────────────────┘
```

Waiting queues the step and notifies when done. Spending under the daily limit proceeds at once; over it, the card says how much over and offers to raise the limit for today only.

### 7.3 Stop a permission (target: two taps)

Permissions → the card → Stop → "Stop this permission? Your helper won't be able to spend on these services." → the marks turn off; Records shows "Stopped by you, [time], on this phone".

### 7.4 Approve from the lock screen

Notification: "Your helper wants to save 'Weekly digest' to Documents." → long-press → Approve → biometrics. The home receives a permission for that one action, valid five minutes.

### 7.5 Lose a phone

On the desktop: Devices → the phone → "I lost this device" → what it could read → Confirm. The phone's permissions stop, the vault key changes, and the next time the phone comes online it is asked to pair again.

## 8. Empty, loading and error states

Every list has an empty state that says what would appear there and offers the one action that fills it. Loading shows the last known content with "Updating…", never a blank screen. Errors follow one pattern: what happened in one sentence, what Muse will do by itself, and one button for what the person can do.

| Situation | Message | Button |
|---|---|---|
| No internet | "You're offline. Your question will be asked when you're back." | — |
| Service busy | "Groq is busy. Trying again at 14:10." | "Use another service" |
| Key refused | "Gemini refused your key." | "Reconnect" |
| Home unreachable | "Can't reach your always-on helper. Last seen 14:02." | "Use this device for now" |
| Records do not match | "Record 1,204 does not match the ones around it." | "What this means" |
| Vault locked | "Unlock to see your private records." | "Unlock" |

## 9. Measures the design is held to

| Flow | Target | How it is measured |
|---|---|---|
| Install to first answer | Under 1 minute, 4 taps, no key | 20-tester study; in-app timing kept on the device |
| One-tap service | Under 1 minute | Same |
| Guided-key service | Under 3 minutes; 10 of 20 testers finish unaided | Same |
| Create a chore | One sentence, one confirmation | Count of taps |
| See what the helper did today | One tap from Today | — |
| Stop everything | One tap from any screen | — |
| Stop one permission | Two taps | — |
| Pair a second device | Under 1 minute | Tester study |
| Add an always-on helper | Under 10 minutes, no terminal | Tester study with non-technical testers |

Timing data stays on the person's device unless they choose to share it.

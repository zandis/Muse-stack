# 健康管理助理：產品與技術規格 v0.2

2026-11-12。這份文件描述核心 app（使用者委託的健康管理助理）與它的第一個可用版本。醫療資料交換是附加功能，預設關閉，本版只定義介面。

本文件不是法律意見。標「需律師」的項目在試點前要先確認。

## v0.2 相對 v0.1 的改動

對應 `docs/reviews/health-bot-spec-review.md` 的發現項。

| ID | 改動 |
|---|---|

## 1. 定位

**一個替使用者處理自己健康事務的助理，照醫療資料的敏感度設計。**

- 使用者：一般 app 使用者，用來管理自己的健康；不限重病病人。
- 發行：先以醫院名義試點，之後轉由公司發行。使用者可帶著加密保險庫整包搬過去；授權與同意不自動延用，見 §3。
- 附加功能：資料交換（加入研究群組、飛地運算、再聯繫）。核心 app 不依賴它。

它做的事：

| 功能 | 是否需要模型 |
|---|---|
| 整理自己的健康紀錄（貼上、匯入檔案） | 否 |
| 用藥、回診、提醒 | 否 |
| 草擬病歷複製本申請信（使用者自己寄） | 否 |
| 準備看診提問清單 | 否 |
| 回答「我的紀錄裡寫了什麼」 | 是 |
| 用白話說明報告內容 | 是 |

它不做的事：診斷、預後數字、是否開始或停止或調整藥物、在治療選項之間做選擇。

遇到緊急症狀：先顯示發行單位的緊急說明，並停止回答該臨床問題；仍可提供非臨床協助，例如 119、醫院急診聯絡方式。判斷方式與測試要求見 §6。

## 2. 四條設計規則

1. **靜態資料只有使用者打得開。** 金鑰由使用者密碼在客戶端派生，解密在瀏覽器（WebCrypto）或之後的裝置 app 進行。伺服器只存密文。磁碟、備份上的資料，代管單位的管理員在靜態時打不開。密碼遺失就無法復原；這是刻意的取捨，復原機制列在 §8。剩餘信任點見 §3：處理當次請求時，app 伺服器與院內模型會在記憶體中看到該次明文。
2. **沒有授權就不動。** 助理的每個動作都要對應一份使用者簽發的授權（範圍、用途、期限、可撤回）。撤回立即生效。敏感授權須使用者在場確認，見 §5。
3. **每個動作都有收據。** 讀了哪些紀錄、送到哪個模型、有沒有內容離開，都寫進使用者看得到的收據。收據本身不含紀錄內文，而以 HMAC 指稱紀錄；收據中繼資料（時間、模型、紀錄種類）同樣敏感，一併加密存放。完整性見 §6。
4. **健康內容只進允許的模型。** 預設只進發行單位自己營運的模型。沒有可用模型時，助理說明原因並停止，絕不改送別處。

## 3. 架構

```
使用者介面（瀏覽器 WebCrypto；之後包成手機 app）
        │  密碼與資料金鑰只留在使用者端
        │  傳給伺服器的是密文；當次提問才送出所需明文
        ▼
app 伺服器 ── 只存密文的保險庫、授權簿、加密的收據日誌
        │      不得把明文、提示或模型回覆寫入日誌或磁碟
        ▼
助理（規則 + 模型）── 僅在處理當次請求時於記憶體使用明文
        │  每個請求帶 x-muse-privacy
        ▼
閘道（LiteLLM + muse hook）── 只放行該隱私等級允許的模型
        │  每個回應附上閘道簽章的 attestation
        ▼
院內的開放權重模型（僅在該次請求中看到明文）
```

**剩餘信任點（須對使用者誠實）：** 當次請求的明文會經過 app 伺服器記憶體，並進入院內模型。能在請求進行時傾印行程記憶體、攔截未加密的院內流量、或從模型主機取走該次輸入的人，仍讀得到該次內容。這不是密碼學保證，而是作業與合約上的控制。之後可用 TEE（或把推理移到使用者裝置）縮小這個範圍。靜態資料與「管理員打開磁碟或備份」不在這個剩餘信任點裡。

閘道就是先前完成的資源管理器。助理端另有一道檢查：回應必須帶著閘道對「實際執行的隱私等級、供應商、部署、時間、請求編號」的簽章（attestation），簽章無效或不符就不採用。閘道簽章金鑰若也被攻破，這道檢查無法防護；它防的是設定錯誤與未持有簽章金鑰的竄改，不是閘道被完全接管。attestation 寫入使用者的收據日誌。

一次提問的路徑：

| 步驟 | 在哪裡 | 明文是否出現 |
|---|---|---|
| 使用者以密碼解鎖；金鑰留在客戶端記憶體 | 瀏覽器 | 是（僅本機） |
| 客戶端選出本次所需紀錄並解密 | 瀏覽器 | 是（僅本機） |
| 經 TLS 把該次問題與所需明文送給 app 伺服器 | 傳輸中 | TLS 保護 |
| 助理套用 §6 規則，必要時呼叫閘道 | app 伺服器 | 是（僅記憶體，用完即丟） |
| 閘道依隱私等級放行，回傳附簽章的 attestation | 閘道／院內模型 | 是（僅該次） |
| 客戶端顯示回覆，並把加密收據寫回伺服器 | 兩端 | 收據中繼資料在客戶端加密後再上傳 |

### 醫院試點與公司發行的差別

差別寫在設定檔（`config/tenants/`）：

| 項目 | 醫院試點 | 公司發行 |
|---|---|---|
| 發行名義與同意文字 | 醫院 | 公司 |
| 個資控制者 | 醫院 | 公司（若有境外營運者，見 §9） |
| 健康內容可進的模型 | 只有院內模型 | 裝置上的模型，或已確認不訓練、不人工審閱且審查未過期的服務 |
| 資料交換附加功能 | 關 | 關（之後由使用者自行開啟） |

搬家流程（發行者變更 = 控制者變更，給醫院的同意與授權不能延用到公司）：

1. 在醫院版匯出保險庫（仍是加密的）。
2. 在公司版匯入密文與舊收據（舊收據只作歷史，不再授權任何動作）。
3. 醫院發行的授權全部標為失效。
4. 使用者閱讀並重新簽署公司版同意書，再重新授予授權之後，公司版助理才能動作。

## 4. 敏感度模型與隱私對照

| 內容 | 等級 | 可以去哪裡 |
|---|---|---|
| 紀錄內文、標題、來源、用藥與回診內容 | 健康 | 只在客戶端與當次請求的記憶體中解密；只進允許的模型 |
| 使用者在對話中輸入的文字 | 健康（一律視同） | 同上 |
| 收據（時間、模型、紀錄種類、HMAC 參照） | 中繼資料，仍屬敏感 | 加密存放；不含紀錄內文 |
| 發行設定、同意書版本 | 公開 | — |

設定檔不允許把健康內容的預設等級設成會放行「拿內容去訓練」的供應商。

閘道隱私等級、收據上的實際去向（Egress）與授權範圍是三個相關但不同的詞。對照如下；實作必須走這張表，不得自行對譯。

| 語意 | 閘道 `x-muse-privacy` | 收據 Egress | 授權範圍 |
|---|---|---|---|
| 沒有內容離開本程序（未呼叫模型） | （無模型呼叫） | `none` | — |
| 院內或使用者裝置上的模型 | `local` | `local` | `llm.local` |
| 已確認不訓練、不人工審閱的合約服務 | `private` | `private` | `llm.private` |
| 其他雲端（可能訓練或人工審閱；預設不可授予） | `standard` 或 `public` | `cloud` | `llm.cloud` |

健康內容的預設與允許清單只能是 `local` 或 `private`，對應 Egress `local` / `private`，不得預設為 `standard` 或 `public`。

`private` 不是自稱即可：`config/providers.yaml` 的該筆政策須記載審查日期（reviewed-on）與重新檢查期限；過期視同不再是 `private`，請求被拒絕，不得降級改送到 `standard` / `public`。

程式碼後續：在 `contracts.py` / `tenant.py` 加入同一張對照，避免兩套詞彙各自解讀。本版規格先以本表為準。

## 5. 授權（mandate）與同意錢包

- 欄位：被授權者、範圍、用途、紀錄種類、到期日、撤回時間、簽章。
- 範圍如下。標「預設」的四項可在首次使用時一次提出，仍須使用者明示同意。

| 範圍 | 含義 | 首次預設 | 簽發方式 |
|---|---|---|---|
| `vault.read` | 讀紀錄以回答問題 | 是 | 明示同意即可 |
| `vault.write` | 依使用者指示新增或刪除紀錄 | 否 | 明示同意 |
| `items.write` | 寫入用藥、回診、提醒 | 是 | 明示同意即可 |
| `llm.local` | 把紀錄內容送院內或裝置上的模型 | 是 | 明示同意即可 |
| `llm.private` | 把紀錄內容送審查未過期的私密服務 | 否 | WebAuthn 在場確認 |
| `llm.cloud` | 把紀錄內容送其他雲端（預設不可授予） | 否 | WebAuthn 在場確認 |
| `draft.letter` | 草擬（絕不寄出）病歷申請或提問清單 | 是 | 明示同意即可 |
| `exchange.view` | 附加功能：看研究邀請 | 否 | 明示同意 |
| `exchange.grant` | 附加功能：授予研究授權 | 否 | WebAuthn 在場確認 |

- 首次使用時，畫面須明確列出擬簽發的預設授權、用途、期限，以及它不包含的範圍（沒有雲端、沒有資料交換）。使用者同意後才簽發，並留下 `mandate.grant` 收據。不得在使用者未看見的情況下自動授予。
- 助理提出的任何寫入都先變成「待確認的變更」，使用者按確認才寫入；確認時再檢查一次授權。

**在場確認：** `exchange.grant`、`llm.cloud`、`llm.private` 必須用 passkey / WebAuthn 做使用者在場確認後才能簽發或變更。這類授權不得用保險庫內、解鎖期間助理也拿得到的 Ed25519 金鑰簽發，以免助理替自己簽名。該 Ed25519 金鑰可用於非敏感操作（例如由已授權動作寫出的收據）。搬家後的重新授權視同新的簽發，適用同一規則。

保險庫、授權與收據構成可攜的**同意錢包（consent wallet）**，寫在核心機制裡，不是附加功能才有：

| 本系統欄位 | 對外對應 |
|---|---|
| 授權的範圍、用途、期限、被授權者、撤回 | HL7 FHIR Consent（provision、purpose、period、grantee） |
| 研究用途代碼、存取級別 | GA4GH DUO（附加功能必填；核心的醫療利用也可選填對應代碼） |
| 同意與授權的收據 | ISO/IEC TS 27560 同意收據欄位 |

匯出格式須讓其他醫院能驗證簽章與效期，而不必依賴本系統在線。這也是設計規劃書 v0.2 收據層的產品形態。

同一種授權物件也用於附加功能：使用者授權研究者使用資料，和授權助理代辦，是同一套機制。

## 6. 安全防線

不依賴模型的規則：

- **緊急症狀**（胸痛、呼吸困難、中風徵象、大量出血、自傷念頭等）：若出現在使用者自己的問題或當下陳述，先顯示發行單位的緊急說明，並停止回答該臨床問題（不解釋可能病因、不給「也許是……」）。仍可提供非臨床協助：119、醫院聯絡方式、如何前往急診。使用者貼上的報告內文與使用者自己的問題分開判斷：僅出現在歷史報告、且問題顯然不是在描述正在發生的急症時，不以急症流程中斷，可加註簡短提醒。須有中文（zh-TW）標註測試集，並公布漏判率與誤判率。規則會漏判，也會誤判，不是保證。
- **醫療建議**（診斷、停藥改藥、結果是否代表得病）：婉拒，並提供把問題加入看診提問清單。解釋名詞與參考範圍是允許的。
- **模型輸出檢查**：指示性的治療用語、斷言式的診斷、不在白名單的數字、不在允許清單的網址或電話。命中就整段換成安全回覆。數字白名單：這次實際取用的來源紀錄裡出現的數字、同一份報告上已印的參考範圍與單位、發行設定中的緊急電話與聯絡資訊。
- **紀錄內文是資料，不是指令**：內文中的指示不會被執行；輸出檢查會攔下照做的回答。
- **引用**：關於使用者紀錄的每個陳述都要引用紀錄編號，且只能引用這次實際取用的紀錄。

**收據完整性：**

- 紀錄參照是 HMAC-SHA256，金鑰由保險庫金鑰經 HKDF 派生（見 §8），不是未加鹽的明文雜湊。
- 本地雜湊鏈讓已解鎖的使用者可以檢查意外毀損，以及沒有簽章金鑰的人插入或刪改單筆收據。它**不能**防住拿得到整個資料庫、整條鏈一起重寫的對手。
- 因此客戶端須定期把檢查點（序號與鏈上雜湊）簽章後送到外部：設計規劃書 v0.2 的透明日誌，或以 EAS 錨定。建議至少每 24 小時、以及每次敏感授權變更時各送一次。沒有外部檢查點時，完整性宣告必須限縮為上述威脅模型，不得寫成「可驗證沒被改寫」而不加限定。

## 7. 附加功能介面（本版不實作）

- 研究邀請以「待使用者決定的授權請求」出現，內容為用途代碼（GA4GH DUO）、存取級別、期限、託管者。
- 使用者同意即簽發一份授權（須 WebAuthn 在場確認，見 §5）；拒絕也留收據。
- 運算一律在託管者的飛地內進行，只有結果離開；每次運算回傳的收據顯示在使用者的動態裡。
- 公開鏈上不出現任何使用者層級的資訊。檢查點錨定只含序號與雜湊，不含身分或紀錄內容。

## 8. 加密規格與已知限制

### 加密規格

| 項目 | 選擇 |
|---|---|
| KDF | Argon2id。記憶體 64 MiB，迭代 3 次，平行度 1，salt 16 bytes（每座保險庫一組，可與密文一起存放），輸出 32 bytes。低階裝置若過慢，可在實測後調整，但不得低於當時 OWASP 建議下限。 |
| 金鑰派生 | 再以 HKDF-SHA256 分開：AEAD 金鑰（`muse.vault.aead.v1`）、收據 HMAC 金鑰（`muse.receipts.hmac.v1`）。密碼與資料金鑰不得離開客戶端。 |
| AEAD | AES-256-GCM（瀏覽器 WebCrypto 原生支援）。96-bit 隨機 nonce，不得重用；128-bit 標籤。AAD 綁定紀錄 id 與 kind。之後的原生 app 可用等價參數的 XChaCha20-Poly1305，須可互操作或一次遷移。 |
| 粒度 | 逐筆加密（標題、內文、來源、提醒與用藥等項目內容）。伺服器可見的明文僅限識別用中繼資料（例如 id、密文長度）。 |
| `search()` | 解鎖後在客戶端建立索引，放在記憶體或以同一套 AEAD 加密後存進 IndexedDB。伺服器沒有明文索引，也不能代搜內文。 |
| 當次請求 | 客戶端解出本次所需紀錄，經 TLS 送給 app 伺服器；伺服器處理完必須丟棄明文，不得寫入磁碟、備份或存取日誌。 |

### 已知限制

- **不是手機 app。** 本版是網頁介面與命令列，適合院內試點與示範。
- **密碼遺失無法復原**是試點的預設。之後的復原設計：裝置、發行單位協助、信任聯絡人三者取二。發行單位持有一份金鑰碎片，代表它有一部分復原權力（再取得另一份即可打開保險庫）。必須寫進同意書；使用者可拒絕把碎片交給發行單位（改為裝置加信任聯絡人，或接受無法復原）。年長使用者的復原體驗需要實測。
- **安全防線是規則，不是保證。** 規則會漏判，也會誤判。緊急與輸出檢查須搭配中文測試集，並追蹤漏判率與誤判率。
- **沒有醫學知識庫。** 白話說明的品質取決於院內模型，本版沒有以臨床人員評估過。
- **匯入格式有限。** 文字、PDF 文字層、FHIR JSON、一般表格。沒有 OCR。健康存摺的匯出格式若無法從公開文件確認，就只走一般格式。
- **同機器上的其他使用者或惡意程式**不在防護範圍內。若能挾持瀏覽器或裝置，就能在解鎖期間取得金鑰。
- **剩餘信任點**見 §3，不會因為客戶端解密而消失。

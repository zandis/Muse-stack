# 健康管理助理：產品與技術規格 v0.1

2026-11-12。這份文件描述核心 app（使用者委託的健康管理助理）與它的第一個可用版本。醫療資料交換是附加功能，預設關閉，本版只定義介面。

本文件不是法律意見。標「需律師」的項目在試點前要先確認。

## 1. 定位

**一個替使用者處理自己健康事務的助理，照醫療資料的敏感度設計。**

- 使用者：一般 app 使用者，用來管理自己的健康；不限重病病人。
- 發行：先以醫院名義試點，之後轉由公司發行。使用者可帶著加密保險庫整包搬過去。
- 附加功能：資料交換（加入研究群組、飛地運算、再聯繫）。核心 app 不依賴它。

它做的事：

| 功能 | 是否需要模型 |
|---|---|
| 整理自己的健康紀錄（貼上、匯入檔案） | 否 |
| 用藥、回診、提醒 | 否 |
| 草擬病歷複製本申請信（使用者自己寄） | 否 |
| 準備看診提問清單 | 否 |
| 回答「我的紀錄裡寫了什麼」 | 是 |
| 用白話說明報告內容 | 是 |

它不做的事：診斷、預後數字、是否開始或停止或調整藥物、在治療選項之間做選擇。遇到緊急症狀只做一件事：請使用者立即就醫。

## 2. 四條設計規則

1. **只有使用者打得開。** 紀錄以使用者密碼衍生的金鑰加密。磁碟、備份、代管單位的管理員都視為不可信。密碼遺失就無法復原；這是刻意的取捨，復原機制列在 §8。
2. **沒有授權就不動。** 助理的每個動作都要對應一份使用者簽發的授權（範圍、用途、期限、可撤回）。撤回立即生效。
3. **每個動作都有收據。** 讀了哪些紀錄、送到哪個模型、有沒有內容離開，都寫進使用者看得到、可驗證沒被改寫的紀錄。收據本身不含任何紀錄內容。
4. **健康內容只進允許的模型。** 預設只進發行單位自己營運的模型。沒有可用模型時，助理說明原因並停止，絕不改送別處。

## 3. 架構

```
使用者介面（網頁，之後包成手機 app）
        │  本機或院內網路
        ▼
app 伺服器 ── 保險庫（加密 SQLite）
        │      授權簿、收據日誌（同一個檔案）
        ▼
助理（規則 + 模型）
        │  每個請求帶 x-muse-privacy
        ▼
閘道（LiteLLM + muse hook）── 只放行該隱私等級允許的模型
        ▼
院內的開放權重模型
```

閘道就是先前完成的資源管理器。助理端另有一道檢查：回應若沒有帶著閘道實際執行的隱私等級，就不採用該回應。

### 醫院試點與公司發行的差別

差別只在一個設定檔（`config/tenants/`）：

| 項目 | 醫院試點 | 公司發行 |
|---|---|---|
| 發行名義與同意文字 | 醫院 | 公司 |
| 健康內容可進的模型 | 只有院內模型 | 裝置上的模型，或已確認不訓練、不人工審閱的服務 |
| 資料交換附加功能 | 關 | 關（之後由使用者自行開啟） |

搬家流程：在醫院版匯出保險庫（仍是加密的）→ 在公司版匯入 → 用同一組密碼開啟。授權與收據跟著走。

## 4. 敏感度模型

| 內容 | 等級 | 可以去哪裡 |
|---|---|---|
| 紀錄內文、標題、來源、用藥與回診內容 | 健康 | 只在記憶體中解密；只進允許的模型 |
| 使用者在對話中輸入的文字 | 健康（一律視同） | 同上 |
| 收據 | 中繼資料 | 不含內容；以內容雜湊指稱紀錄 |
| 發行設定、同意書版本 | 公開 | — |

設定檔不允許把健康內容的預設等級設成會放行「拿內容去訓練」的供應商。

## 5. 授權（mandate）

- 欄位：被授權者、範圍、用途、紀錄種類、到期日、撤回時間、簽章。
- 範圍：讀紀錄、寫紀錄、寫提醒、送院內模型、送私密服務、送一般雲端（預設不可授予）、草擬信件、（附加功能）看研究邀請、授予研究授權。
- 首次使用時簽發預設授權：讀紀錄、寫提醒、草擬信件、送院內模型。
- 助理提出的任何寫入都先變成「待確認的變更」，使用者按確認才寫入；確認時再檢查一次授權。

同一種授權物件也用於附加功能：使用者授權研究者使用資料，和授權助理代辦，是同一套機制。

## 6. 安全防線

不依賴模型的規則：

- **緊急症狀**（胸痛、呼吸困難、中風徵象、大量出血、自傷念頭等）：回覆最前面顯示發行單位的緊急說明。使用者貼上的報告內文與使用者自己的問題分開判斷。
- **醫療建議**（診斷、停藥改藥、結果是否代表得病）：婉拒，並提供把問題加入看診提問清單。解釋名詞與參考範圍是允許的。
- **模型輸出檢查**：指示性的治療用語、斷言式的診斷、來源紀錄裡沒有的數字、不在允許清單的網址或電話。命中就整段換成安全回覆。
- **紀錄內文是資料，不是指令**：內文中的指示不會被執行；輸出檢查會攔下照做的回答。
- **引用**：關於使用者紀錄的每個陳述都要引用紀錄編號，且只能引用這次實際取用的紀錄。

## 7. 附加功能介面（本版不實作）

- 研究邀請以「待使用者決定的授權請求」出現，內容為用途代碼（GA4GH DUO）、存取級別、期限、託管者。
- 使用者同意即簽發一份授權；拒絕也留收據。
- 運算一律在託管者的飛地內進行，只有結果離開；每次運算回傳的收據顯示在使用者的動態裡。
- 公開鏈上不出現任何使用者層級的資訊。

## 8. 已知限制

- **不是手機 app。** 本版是網頁介面與命令列，適合院內試點與示範。
- **密碼遺失無法復原。** 之後的復原設計：裝置、發行單位協助、信任聯絡人三者取二。年長使用者的復原體驗需要實測。
- **安全防線是規則，不是保證。** 規則會漏判，也會誤判。
- **沒有醫學知識庫。** 白話說明的品質取決於院內模型，本版沒有以臨床人員評估過。
- **匯入格式有限。** 文字、PDF 文字層、FHIR JSON、一般表格。沒有 OCR。健康存摺的匯出格式若無法從公開文件確認，就只走一般格式。
- **同機器上的其他使用者或惡意程式** 不在防護範圍內。

## 9. 試點前要確認的事

| 項目 | 對象 |
|---|---|
| 說明報告內容是否構成醫療行為或醫療器材軟體 | 律師、醫院法務（需律師） |
| 試點屬於研究還是品質改善，是否需 IRB | 醫院 IRB |
| 院內模型的選擇、硬體與維運 | 醫院資訊室 |
| 緊急說明與危機專線的文字 | 醫院臨床主管 |
| 公司發行後公司的個資角色（本機優先、公司讀不到內容） | 律師（需律師） |
| 白話說明的正確性評估方式 | 臨床人員 |
